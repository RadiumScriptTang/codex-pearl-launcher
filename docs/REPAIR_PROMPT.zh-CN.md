# 在本机用 Codex 修复或适配

适用于安装后点击没有反应、开场没有声音、窗口交接失败，或系统 / Codex 更新后不兼容。本提示词让 Codex 在发生问题的电脑上排查，不需要把日志来回搬到另一台机器。

这是排障入口，不代表当前版本已在你的环境验证通过；可复现的问题仍应修回项目。

## 怎么用

1. 从 [Release](https://github.com/RadiumScriptTang/codex-pearl-launcher/releases) 下载对应平台的完整安装包并解压。保留解压后的整个文件夹；仅下载 GitHub 的 Source code 不含运行时。
2. 在出问题的电脑上，用 Codex 打开解压目录内的「程序文件」文件夹作为项目；旧版 alpha.1 包则打开 `codex-pearl-launcher` 文件夹。直接克隆仓库时打开仓库根目录。
3. 把下面整段提示词粘进新聊天。可以在末尾补一句实际现象，例如「安装成功，桌面 App 双击后没有任何反应」。
4. 让它在本机完成排查与修复。需要重新打开当前 Codex 时，由你手动操作。

## 可直接复制的提示词

```text
请在这台电脑上修复并适配当前 Codex Pearl Launcher 项目，实际修改代码、验证结果，不要只给我排查建议。

目标流程：点击安装生成的入口 → 海祇通行开场 → 心海描线、飘发、睁眼，配已有语音和混音 → 平滑显露 Codex 新聊天。保留现有图片、配色、动画节奏、语音和图标；不要重新生成素材或重做整个方案。

先读项目的 AGENTS.md（如有）、README.md、RELEASE_NOTES.md 和 ASSETS.md，再根据本机平台追踪真实启动链。先给出简短判断并继续动手，不要让我先收集一长串资料或把你能直接读取的日志粘给你。

一、先用本机证据定位问题
- 识别操作系统版本、CPU 架构、实际安装的官方 Codex 及其位置。不要假定 ChatGPT 与 Codex 是同一个 App，也不要因为我说 GPT 就认定已安装 Codex。
- 区分「下载解压目录」「安装后的启动器」「官方 Codex」。核对入口实际指向哪一份文件，避免修了源码却仍然测试旧安装副本。
- 检查启动脚本、内置 Node 是否可执行、原生窗口宿主、HTML 构建结果和媒体资源。先记录原始错误，再选择最小修复；不要先认定是权限问题。
- 优先运行不打开 Codex 的检查：内置 Node --version、构建、npm run check、npm test，以及平台原生组件检查。没有 npm 时可用内置 Node 分别运行 scripts/build.cjs、scripts/check.cjs、scripts/smoke.cjs。
- 注意：npm test 只验证回环通信与模拟状态，不代表真实的 AppKit/WebKit、声音、窗口或新聊天跳转已经通过。

macOS 线索（按证据选择检查，不是预设根因）：
- 入口通常为 ~/Applications/Codex Pearl.app；桌面通常是指向它的链接。
- 资源在 App 内 Contents/Resources/app；主入口是 Contents/MacOS/CodexPearl，然后进入 launcher.cjs / launcher-v8.cjs，再启动 mac/host.js。
- 日志通常是资源目录中的「启动日志.txt」，状态文件在 runtime/。如果进程在日志创建前就退出，从终端运行该启动器入口，捕获 stdout、stderr 和退出码。
- 单独检查内置 vendor/darwin-arm64/bin/node，以及 /usr/bin/osascript -l JavaScript mac/host.js --self-test；这些检查通过后仍要验证真实窗口和 WebKit 页面。
- 检查 App Bundle、可执行位、脚本换行、路径引号、动态库 / 最低系统版本、JXA 与 Objective-C 桥接、事件循环、WebKit 加载和媒体播放。当前 Mac 发行范围仅 Apple Silicon。

Windows 线索：
- 安装目录通常为 %LOCALAPPDATA%\CodexPearlLauncher；核对桌面快捷方式、launch.ps1、内置 Node、launcher-v8.cjs 和 handoff.ps1。
- 检查 Edge 的实际位置、窗口发现与交接状态，不要把有素材的 HTML 能打开视为原生交接已通过。

二、修复并让失败可见
- 用证据说明根因，只改解决问题所需部分；兼容性分支应依据实际版本或能力检测。
- 启动失败应给用户可读的错误提示，并留下日志位置、原始错误和退出码；不能再次静默退出。日志不要包含令牌、Cookie 或聊天内容。
- 修改源项目，必要时同步更新安装脚本和已安装副本；覆盖前备份本启动器被修改的文件。不能只给本机打补丁，却保留仍会安装坏版本的安装器。
- 不删除或替换官方 Codex，不修改聊天数据库，不结束或自动重启我正在使用的 Codex。如需重启当前 Codex，说明原因并让我手动完成；只可管理本次测试创建的启动器进程和窗口。
- 不通过关闭 Gatekeeper、SIP、杀毒软件或移除隔离属性来掩盖问题。若遇到系统安全拦截，报告具体提示，说明系统提供的手动确认方式；不要声称未签名应用已签名或已公证。
- 不额外上传我的日志、不发布仓库 / Release、不使用我的账号发送消息。修复验证不需要向聊天输入框提交任何内容。

三、在本机验收
- 先通过适用的静态检查、构建与通信测试，再测试安装生成的真实入口。
- 验证：窗口出现 → 图片完整 → 实际声音播放 → 动画走完 → 官方 Codex 新聊天打开 → 过渡后开场窗口退出；再验证第二次启动，排除残留进程 / 锁导致无反应。
- 用本机可以取得的窗口、页面、日志等证据验证；没有音频回录或人工确认时，媒体状态只能证明播放进度，不能声称已经听到声音。无法亲自观察的部分请我简短确认，不要笼统宣称全部通过。
- 皮肤属于实验附加功能，应单独检查能力和依赖。主流程修复不能被它阻塞；不能把缺失的 Dream Skin 辅助脚本或未验证的 Mac 皮肤当作已支持。
- 更新 README：明确下载哪个文件、如何解压和安装、安装到哪里、下一步点哪个入口，以及失败时怎样看日志。

完成后用简短中文报告：已证实的根因、改了哪些文件、真实通过了哪些测试、还需我确认什么。若被外部条件阻塞，保留诊断结果和已完成修复，只问继续所必需的一件事。
```

## 向项目反馈（可选）

可让本机 Codex 整理不含个人路径、令牌和聊天内容的根因摘要、系统版本、修改 diff 与复现步骤，再由你决定是否提交 Issue 或 PR。不要直接上传整份日志目录。
